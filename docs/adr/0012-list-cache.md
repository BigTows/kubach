# 0012 — Кэш списков ресурсов на диске

Статус: принято

## Контекст
Список вида (Pods, Deployments…) появлялся только после полного list: при каждом запуске,
переключении контекста, вида или namespace — пустой экран «Loading…», на больших
кластерах — секунды. Watch при этом умирал вместе с последней подпиской, и возврат в
только что открытый namespace снова делал полный list (#300).

## Решение
- **Stale-while-revalidate.** Последний загруженный список каждого вида хранится на диске
  (`kubach-core::list_cache`) и показывается сразу, пока идёт обычный list+watch; по
  приходу полного списка он подменяется в той же таблице (выделение и прокрутка
  сохраняются). Пока обновление идёт, в статус-баре тонкий индетерминированный
  `LoadingBar` (`kubach-ui`). Без подключения или API discovery показывается
  последний список с пометкой «из кэша»; при ошибке подключения он остаётся.
- **Ключ** — контекст, `(group, kind)` и namespace (или «все namespace» для выбора всех и
  для cluster-scoped видов), как у watch. Выбор нескольких namespace собирается из записей
  по каждому; если хоть одной нет, кэш не показывается — частичный список не выдаётся за
  полный.
- **Чувствительные данные не пишутся.** Secrets не кэшируются совсем (даже с вырезанными
  значениями); у остальных объектов удаляются `managedFields` и
  `last-applied-configuration`.
- **Ограничения.** Формат с версией, gzip; запись не больше 10 000 объектов и 8 МиБ, всего
  до 200 записей и 64 МиБ, вытесняются давно не читанные. Битый файл, файл другой версии
  или другого ключа игнорируется и удаляется. Каталог — `<config dir>/cache/lists`
  (`KUBACH_CONFIG_DIR`), его чистит «Clear cache».
- **Запись в фоне.** `ListWriter` копит последний список на ключ и пишет его через
  `runtime::blocking` не чаще раза в `WRITE_DELAY` (3 с); чтение — на background executor
  GPUI. Главный поток диска не касается.
- **Watch в памяти.** Отпущенный watch работает ещё `LINGER` (90 с, не больше 8 штук,
  вытесняется давно отпущенный) и в статус «Syncing» не входит; watch одного namespace,
  пока грузится, отдаёт объекты своего namespace из загруженного watch всех namespace.

## Последствия
- Повторное открытие вида, кластера или namespace показывает данные мгновенно; переключение
  namespace туда-обратно не делает нового list.
- Кэшированные данные могут быть устаревшими: в строке счётчика пометка «cached N ago»,
  действия над объектами без подключения недоступны.
- Принцип «watch только у активного экрана» ослаблен на `LINGER`: несколько watch живут до
  90 с после ухода с экрана.
