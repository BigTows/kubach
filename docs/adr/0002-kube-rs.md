# 0002 — kube-rs для ядра

Статус: принято

## Контекст
Ядру нужен клиент Kubernetes API с поддержкой kubeconfig, watch и динамических ресурсов (CRD).

## Решение
Строить `kubach-core` на [`kube-rs`](https://kube.rs). Крейт не имеет UI-зависимостей.

## Последствия
- Готовые list/watch, reflector и динамические API.
- Ядро тестируется и переиспользуется (в том числе MCP) без UI.
- Привязка к async-рантайму (tokio): на границе с GPUI её нужно оформить аккуратно.
  Вопрос решён в [ADR 0011](0011-async-runtime.md): общий рантайм, задачи с владельцем и отменой.

## Версии Kubernetes
`k8s-openapi` собирается с фичей `latest`: сейчас это типы Kubernetes 1.37. Фича задаёт только
форму структур на этапе сборки; версию сервера клиент не сверяет и не отказывает старым кластерам.
Upstream поддерживает 1.33–1.37, это и есть наш ориентир: минимальная версия в коде не проверяется.

- Типизированно читаются только группы GA (`apps/v1`, `core/v1`, `batch/v1` и т. п.), они есть во всех
  этих версиях. Всё остальное идёт через `DynamicObject` и обнаружение API.
- Чтение объекта старого сервера не падает: отсутствующие обязательные поля декодируются как значения
  по умолчанию, отсутствующие необязательные — как `None`. Исключения `k8s-openapi` (`lastTransitionTime`
  в `meta/v1 Condition`, `lastObservedTime` в `EventSeries`) не изменились.
- С 1.37 `spec` у `Deployment`, `StatefulSet`, `DaemonSet` и `ReplicaSet` не `Option`, поэтому отсутствие
  `spec` неотличимо от значения по умолчанию, а пустой селектор выбирает все поды. Плагины рабочих
  нагрузок смотрят на `spec` через `present()`: значение по умолчанию там считается отсутствием.
- Обратное изменение: `type` и `status` условий этих ресурсов стали `Option`; условие без них ни с чем
  не совпадает, как и раньше с пустой строкой.
- Типизированный объект теперь всегда сериализует `spec`. Для частичных патчей используется JSON,
  а не такая структура.

## Что учитывать в kube 5
- Stdout и stderr `AttachedProcess` — `SimplexStream`: потеря половины записи их не закрывает.
  EOF приходит только при штатном завершении задачи kube, а при `abort()` или обрыве соединения чтение
  зависло бы. `streams/exec.rs` читает их через `UntilFinished`, который заканчивает чтение с концом
  соединения. Stdin закрывается только явным `shutdown()`.
- kube сверяет `NO_PROXY` с адресом прокси, а не API-сервера, и отказывает контексту, если не разобрал
  список (`localhost,`). Поэтому прокси выбирает `cluster::take_proxy_url` по прежнему правилу: `proxy-url`
  кластера, затем `HTTPS_PROXY`, без учёта `NO_PROXY`. Ограничение: если задан `HTTPS_PROXY` и `NO_PROXY`
  не разбирается, ошибка остаётся: это проверка внутри kube, из кода её не обойти. У `proxy-url` такой проблемы нет.
- kube отправляет `as-uid` и `as-user-extra` из kubeconfig. Для имперсонации сессии MCP они сбрасываются:
  они относятся к личности из kubeconfig, а не к личности сессии.
- Ошибки HTTP на WebSocket-upgrade (exec, attach, port-forward) теперь приходят как `kube::Error::Api`
  с `Status` сервера.
